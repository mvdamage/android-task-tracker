# TZ-002: Голос и AI — расширение захвата

- Версия документа: 0.1
- Статус: draft
- Дата: 2026-09-28
- База: [TZ-001](TZ-001-voice-input.md) (голос для задач и покупок уже есть)
- Платформа: Android, Jetpack Compose, offline-first БД
- Оценка: M (парсеры + confirm) → L (если подключаем внешний LLM)

## 1. Цель

Расширить голосовой/текстовый захват на **события**, **дни рождения** и **заметки**; дать разбор длинного текста в несколько сущностей и умные подсказки категории покупок — с обязательным confirm до записи в БД.

## 2. Scope

### In (MVP)

| ID | Возможность | Приоритет |
|----|-------------|-----------|
| V-AI-01 | Голос на вкладке **Заметки**: текст → заметка TEXT или LIST | Must |
| V-AI-02 | Голос на **календаре / создание события**: фраза → EVENT (дата, время, место) | Must |
| V-AI-03 | Голос «день рождения …» → BIRTHDAY (дата, имя) | Must |
| V-AI-04 | Confirm sheet для заметок / события / ДР (правка до сохранения) | Must |
| V-AI-05 | Разбор **длинного текста** (из буфера или поля) → несколько задач / пунктов списка | Should |
| V-AI-06 | Подсказка категории покупки по названию (история + правила), без автосоздания категорий | Should |

### Out

- Свой cloud STT / обязательный онлайн LLM (Could отдельно)
- Wake word, системный Assistant
- Автосейв без confirm
- Голосовое редактирование уже созданных сущностей
- Перевод речи в приоритет / сложные повторы (кроме YEARLY для ДР)

## 3. Сценарии

### Happy path — заметка (TEXT)

1. Mic на «Заметки» → listening.
2. «Идеи для отпуска: море, горы, бюджет».
3. Parser → format=TEXT, title (из начала или «Без названия»), body=полный текст, theme=IDEAS если есть маркер «идеи», иначе GENERAL.
4. Confirm → правка → «Добавить».

### Happy path — заметка (LIST)

1. «Список дел: купить билеты, собрать аптечку, позвонить гиду».
2. Parser → format=LIST, title «Список дел», пункты без префикса.
3. Confirm: пункты редактируемы → сохранить.

### Happy path — событие

1. «Встреча с клиентом завтра с 14 до 15 в офисе на Арбате».
2. Parser → kind=EVENT, title, date, time range, location.
3. Confirm → «Добавить».

### Happy path — ДР

1. «День рождения Анны 15 марта».
2. Parser → kind=BIRTHDAY, title=Анна (или «День рождения Анны»), date=15.03 текущего/ближайшего года, recurrence=YEARLY.
3. Confirm → «Добавить».

### Happy path — длинный текст → задачи (Should)

1. Пользователь вставляет / диктует абзац с несколькими действиями.
2. Parser выделяет 2+ черновика задач (title + опционально дата).
3. Confirm-список: правка, удаление строк, «Добавить (N)».

### Ошибки / edge

| Ситуация | Поведение |
|----------|-----------|
| Пустой STT / отмена | Нет записи в БД |
| Не удалось определить тип | Confirm как TEXT-заметка с raw текстом **или** выбор типа вручную на confirm |
| Нет даты у события | Дата = выбран выбран / выбран календаря; на confirm обязательна |
| ДР без дня/месяца | Confirm без автодаты; сохранить нельзя, пока дата не задана |
| Пункты списка пустые после очистки | «Добавить» disabled |
| Категория покупки не найдена | null; пользователь выбирает на confirm |

## 4. UI

| Место | Поведение |
|-------|-----------|
| Заметки | FAB-колонка: Add + Mic (как задачи/покупки) |
| Календарь | Mic рядом с плашками создания **или** mic на FAB задач при выбран=EVENT/BIRTHDAY — зафиксировать в реализации один вариант |
| Confirm заметки | title, format (Текст/Список), theme, body **или** список пунктов |
| Confirm событие | title, date, time/period, location |
| Confirm ДР | title (кто), date |
| Confirm multi-task | список черновиков, как shopping confirm |
| First-run | тот же voice disclaimer, что TZ-001 |

Состояния сессии: idle → listening → processing → confirm / error (переиспользовать `VoiceCaptureController`).

## 5. Данные и правила

### Парсеры (локальные, ru-RU)

| Парсер | Вход | Выход |
|--------|------|-------|
| `NoteVoiceParser` | raw | title, format TEXT\|LIST, theme?, body?, listItems[] |
| `EventVoiceParser` | raw | title, dueDate, dueTime?, dueTimeEnd?, location? |
| `BirthdayVoiceParser` | raw **или** ветка Task/Event | title, dueDate (день+месяц), kind=BIRTHDAY |
| `BulkTaskParser` (Should) | raw абзац | List\<TaskDraft\> |
| Усиление `ShoppingVoiceParser` (Should) | title | suggestedCategoryId? |

### Правила

- Max длина поля как в TZ-001 (200 для title/пункта; body заметки — до 4000).
- LIST: маркеры «список», «пункты», перечисление через запятую / «и» / перенос строки.
- EVENT: слова «встреча», «событие», «созвон» + дата/время; location — хвост после «в»/«на» (эвристика, правится на confirm).
- BIRTHDAY: «день рождения», «др»; дата без года → ближайшая будущая дата с этим днём/месяцем.
- Конфликт EVENT vs BIRTHDAY: явный «день рождения» → BIRTHDAY, иначе EVENT.
- Подсказка категории покупки: (1) точное совпадение title в истории, (2) иначе null. Без сетевого словаря в MVP.

### Сохранение

Только после confirm → существующие `addTask` / `addNote` / `addItem`. Без обхода нормализации `TaskKindRules` / notes rules.

## 6. NFR

- Без обязательного интернета сверх системного STT (как TZ-001).
- Парсинг на устройстве; ответ confirm < 300 ms на типичной фразе (без LLM).
- Unit-тесты парсеров (минимум таблица из §3).
- Смена вкладки отменяет listening; confirm state переживает поворот (как TZ-001).

## 7. Критерии приёмки (DoD)

- [ ] Mic на Заметках создаёт TEXT и LIST через confirm
- [ ] Голосовое событие заполняет дату/время/место (если сказаны) и сохраняется как EVENT
- [ ] Голосовой ДР сохраняется как BIRTHDAY с YEARLY
- [ ] Нет записи в БД до «Добавить» на confirm
- [ ] Ошибки STT / пустой результат — без краша, с сообщением
- [ ] Unit-тесты парсеров зелёные
- [ ] (Should) Bulk text → N задач с confirm
- [ ] (Should) Подсказка категории на confirm покупки из истории
