# F-003: Бэкап и восстановление

- Статус: draft
- Приоритет: Must
- Эпик: Бэкап / экспорт
- Связанное ТЗ: —

## User story

Как пользователь, заботящийся о приватности (P3), я хочу экспортировать все данные приложения в файл и позже восстановить их, чтобы не потерять задачи и покупки при смене или сбросе телефона.

## Контекст / проблема

Продукт осознанно без облака. Без экспорта/импорта смена устройства = потеря данных — риск, которого нет у sync-first конкурентов. Локальный бэкап — компенсация non-goal «нет sync».

## Acceptance criteria

1. Given пользователь в настройках, When выбирает «Экспорт», Then создаётся файл бэкапа, который можно сохранить через системный share/SAF.
2. Given валидный файл бэкапа, When пользователь выбирает «Восстановить / Импорт», Then после подтверждения данные приложения заменяются содержимым файла.
3. Given импорт, When завершён успешно, Then на месте: задачи, подзадачи, настройки в scope, списки задач (после F-002), элементы и категории покупок.
4. Given повреждённый или чужой формат файла, When импорт, Then показывается понятная ошибка, текущие данные **не** портятся.
5. Given диалог импорта, When пользователь не подтвердил замену, Then изменения не применяются.
6. Given экспорт, When файл открыт вне приложения, Then это документированный формат (версия схемы в файле), пригодный для повторного импорта этой же или более новой версии приложения (обратная совместимость читать N−1 — цель ТЗ).

## Бизнес-правила

- Импорт в v1 = **полная замена** данных (не merge), с явным предупреждением.
- Бэкап не требует аккаунта и сети.
- Пароли/шифрование файла — вне минимального Must; Could «пароль на архив».
- Автобэкап по расписанию — Could; v1 достаточно ручного export/import.

## Вне scope

- Облачная синхронизация, автозагрузка в Google Drive как обязательная фича (пользователь может сам сохранить файл куда угодно)
- Выборочный экспорт только задач или только покупок (можно добавить позже)
- Continuous backup / point-in-time history

## Зависимости

- B-001…B-007, F-002 (включать списки в схему после появления)
- Доступ к Storage Access Framework / share sheet
