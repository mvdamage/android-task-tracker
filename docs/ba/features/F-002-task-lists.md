# F-002: Списки задач

- Статус: draft
- Приоритет: Must
- Эпик: Списки / проекты
- Связанное ТЗ: —

## User story

Как личный планировщик (P1), я хочу группировать задачи по именованным спискам, чтобы при большом числе дел быстро находить нужный контекст (работа, дом, учёба).

## Контекст / проблема

Сейчас плоский список + фильтр статуса. На рынке минимум паритета — списки/проекты (MS To Do, Google Tasks, Todoist). Без группировки >30–50 задач ухудшает ориентацию.

## Acceptance criteria

1. Given пользователь, When создаёт список с названием, Then список появляется в навигации/выборе.
2. Given задача, When пользователь назначает список (при создании или редактировании), Then задача принадлежит этому списку.
3. Given выбран список, When открыт экран задач, Then показаны только задачи этого списка (с учётом фильтра статуса).
4. Given режим «Все списки» (или эквивалент), When пользователь его выбирает, Then видны задачи из всех списков.
5. Given список без задач, When пользователь удаляет список, Then список исчезает.
6. Given список с задачами, When пользователь удаляет список, Then система требует выбора: перенести задачи в другой список / «Входящие» или отменить удаление (не молчаливая потеря).
7. Given новая установка, When пользователь ещё не создавал списки, Then есть системный список по умолчанию (например «Входящие»), и существующие задачи к нему привязаны после миграции.

## Бизнес-правила

- Модель v1: **плоские именованные списки** (без секций и вложенных проектов).
- Задача принадлежит **ровно одному** списку.
- Список покупок — отдельная сущность приложения, **не** смешивается со списками задач.
- Переименование списка не меняет принадлежность задач.
- Пустое имя списка запрещено; имена уникальны без учёта регистра (гипотеза — подтвердить в ТЗ).

## Вне scope

- Секции внутри списка, иерархия проектов
- Метки / мультисписки у одной задачи
- Шаринг списка
- Цвета/иконки списков (Could UI)

## Зависимости

- Миграция существующих задач → список по умолчанию
- F-004 (Мой день) может агрегировать cross-list — учитывать при проектировании
