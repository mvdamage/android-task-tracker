# Требования к продукту: Task Tracker

- Версия: 0.3

## Проблема и ценность

Пользователь держит в голове бытовые и личные обязательства (дела, дедлайны, покупки). Облачные планировщики требуют аккаунт, подписку и часто неоплачиваемы из РФ; простые списки не закрывают сроки и повторы.

**Ценность:** локальный Android-органайзер без аккаунта — задачи с нормальным планированием + список покупок, офлайн и приватность как преимущество.

## Персоны

| ID | Персона | Контекст | Главная потребность |
|----|---------|----------|---------------------|
| P1 | Личный планировщик | 1 устройство, учёба/работа/быт | Не забыть дела со сроками и повторами |
| P2 | Домашний органайзер | Семья/быт, покупки | Одинアプリ для дел и списка в магазин |
| P3 | Privacy-conscious | Не хочет облако/аккаунт | Данные только на устройстве + бэкап |

> Семья/шаринг и микрокоманда — **не** целевые персоны v1 (см. Non-goals), пока стейкхолдер не решит иначе.

## Цели продукта

1. Дать полный цикл личного планирования на одном Android-устройстве без регистрации.
2. Закрыть gap паритета рынка: напоминания, базовая организация списков, защита от потери данных.
3. Усилить дифференциатор «задачи + покупки» как домашний органайзер.
4. Сохранить офлайн-first и работу без обязательного аккаунта.

## Non-goals (горизонт v1 / ближайший релизный цикл)

- Облачный sync и мультиустройство (Could; осознанно вне scope, пока нет решения стейкхолдера)
- iOS / web-клиенты
- Командная работа, назначение исполнителей, шаринг списков
- Привычки, Pomodoro, kanban, метки/умные фильтры уровня Todoist
- Расширенный NLP из речи/текста: приоритет, повторы, «через час», автосоздание категорий (базовый срок задачи и категория покупки из голоса — в F-008)
- Монетизация / подписки

## Открытые решения стейкхолдера

Блокируют уточнение scope (из market-анализа):

1. Позиционирование: «таск-менеджер» vs «домашний органайзер (задачи + покупки)»? → влияет на F-005 и приоритет F-008.
2. Облако когда-либо нужно? → держим C-004 вне v1 до ответа.
3. Android-only на 6–12 мес.? → предполагаем **да**.
4. Списки (F-002): плоские именованные списки или иерархия проектов/секций? → в F-002 заложен **плоский список** (минимум паритета).
5. Голос (F-008): system STT + интернет допустим. Парсинг даты/времени задачи и категории покупки — **в scope** (см. TZ-001).
