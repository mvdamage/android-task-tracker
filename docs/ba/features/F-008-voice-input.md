# F-008: Голосовое добавление задач и покупок

- Статус: draft
- Приоритет: Should
- Эпик: Голосовой захват
- Связанное ТЗ: [TZ-001](../tz/TZ-001-voice-input.md)
- Связь: усиливает F-005 (домашний органайзер), F-007 (быстрый захват); расширяет бывший C-005 в части даты/времени задачи и категории покупки

## User stories

### F-008a — Задача голосом

Как личный планировщик (P1) или домашний органайзер (P2), я хочу создать задачу голосом с распознаванием даты и времени исполнения, чтобы не заполнять срок вручную после диктовки.

### F-008b — Покупка голосом

Как домашний органайзер (P2), я хочу добавить один или несколько пунктов в список покупок голосом с определением категории, чтобы сразу видеть их в нужной группе.

## Контекст / проблема

Ручной ввод через bottom sheet достаточен за столом, но в быту печать замедляет захват. Голос ускоряет создание; без парсинга атрибутов пользователь всё равно открывает форму, чтобы выставить срок или категорию — ценность голоса падает.

**Ограничение продукта:** офлайн-first и без аккаунта. STT часто нуждается в сети (системный SpeechRecognizer) — компромисс с дисклеймером.

## Acceptance criteria

### Общие

1. Given пользователь на вкладке «Задачи» или «Покупки», When доступен голосовой захват, Then виден понятный элемент управления без обязательного открытия полной формы сначала.
2. Given permission на микрофон не выдано, When пользователь запускает голос, Then rationale + системный запрос; при отказе — объяснение и ручной ввод.
3. Given идёт запись/распознавание, When пользователь отменяет, Then ничего не сохраняется в базу.
4. Given распознавание вернуло пустой результат, When завершение сессии, Then «Не удалось распознать речь», запись не создаётся.
5. Given успешное распознавание, When получен текст, Then открывается confirm с возможностью править все распознанные атрибуты до сохранения.

### Задачи (F-008a)

6. Given вкладка «Задачи», When пользователь надиктовал фразу и подтвердил, Then создаётся **одна** активная задача с названием после очистки от токенов срока.
7. Given фраза содержит распознаваемый маркер даты и/или времени (см. бизнес-правила), When открыт confirm, Then поля даты/времени предзаполнены результатом парсинга.
8. Given фраза без маркеров срока, When confirm, Then дата и время пустые (как ручное создание без срока).
9. Given пользователь на confirm изменил дату/время или сбросил их, When сохранение, Then в БД попадают значения с confirm, а не «сырой» парсинг.
10. Given сохранение успешно, Then задача видна в списке; Snackbar «Задача добавлена».
11. Given после F-002 есть текущий список, When задача создана голосом, Then она в текущем списке (или «Входящие»).

### Покупки (F-008b)

12. Given одна позиция без категории в речи, When confirm, Then пункт с title и category по правилам назначения (§ бизнес-правила).
13. Given перечисление, When разбор, Then отдельный пункт на фрагмент; категория считается **для каждого** пункта отдельно.
14. Given в фрагменте или общей фразе указана категория (имя существующей категории пользователя), When confirm, Then у пункта предвыбрана эта категория; токены категории убраны из названия пункта.
15. Given категория не извлечена из речи, When есть история: такой же title уже сохраняли с категорией, Then подставляется эта категория (как у `addSuggestedItem`).
16. Given категория не найдена ни из речи, ни из истории, Then `categoryId = null` (без категории).
17. Given confirm, When пользователь меняет категорию пункта или снимает её, Then сохраняется выбор с confirm.
18. Given сохранение, Then пункты в списке, бейдж активных обновлён; категории отображаются как при ручном создании.

## Бизнес-правила

### Нормализация текста

- Trim; схлопывание пробелов; регистр STT сохранять; max 200 символов на название (обрезка с индикацией на confirm).

### Разбор покупок (перечисление)

- Разделители: `,` `;` `\s+и\s+` (case-insensitive), перевод строки.
- Не дробить по пробелам («зубная паста» = 1 пункт).
- Confirm со списком пунктов обязателен.

### Парсинг даты и времени задачи (русский, локальный часовой пояс устройства)

Парсер применяется к **одной** фразе задачи до confirm. Результат: `{ titleClean, dueDateEpochDay?, dueTimeMinutes?, dueTimeEndMinutes? }`.

**Дата (достаточно одного совпадения; приоритет — первое слева направо, конфликт двух дат → первое + не молчать: на confirm показать результат):**

| Паттерн (примеры) | Интерпретация |
|-------------------|---------------|
| сегодня | epochDay = сегодня |
| завтра | сегодня + 1 |
| послезавтра | сегодня + 2 |
| в понедельник … в воскресенье / в пн…вс | ближайший такой день недели **в будущем** (если сегодня этот день и время уже указано в прошлом — следующий; если только дата без времени — этот день, если ещё не прошёл календарный день, иначе следующий) |
| через N день/дня/дней | сегодня + N |
| DD.MM / DD.MM.YYYY / «N января\|…\|декабря» [года] | календарная дата; год по умолчанию — текущий, если дата не в прошлом более чем на 1 день, иначе следующий год (уточнение в unit-тестах ТЗ) |

**Время:**

| Паттерн | Интерпретация |
|---------|---------------|
| в H:MM / в H часов / в H | `dueTimeMinutes` = H*60+MM (24h) |
| в H утра / дня / вечера / ночи | 12h-стиль → 24h (утро 0–11, день 12–16, вечер 17–22, ночь 23–5 с переносом логики «в 1 ночи» → 01:00) |
| с H:MM до H:MM / с H до H | `dueTimeMinutes` + `dueTimeEndMinutes` (интервал, end > start) |

**Очистка названия:** найденные токены даты/времени и служебные предлоги («в», «на», «к» в составе совпадения) удаляются из строки названия; затем normalize. Если после очистки title пуст — оставить исходную фразу без парсинга срока (fail-soft) **или** показать ошибку «Не удалось понять название» — в ТЗ зафиксирован fail-soft: без срока, title = normalize(raw).

**Не парсить в v1:** повторы («каждый день»), приоритет («срочно», «p1»), относительное «через час» без даты (можно как Could: сегодня + now+60 мин).

**Повторы:** всегда `NONE` при голосовом создании v1.

### Назначение категории покупки

Для каждого пункта после split (и опционально после извлечения явной категории из фрагмента):

1. **Явное указание в тексте фрагмента** (или общее для всей фразы, если один пункт):  
   «в категорию X», «категория X», «в X» где X **точно или без учёта регистра совпадает с `ShoppingCategoryEntity.name`** существующей категории пользователя.  
   Токены указания убрать из title.
2. Иначе **история по title** (как текущий `categoryByTitle` / `addSuggestedItem`): последнее `categoryId` для того же title (lowercase trim).
3. Иначе **null**.

Не создавать новую категорию голосом автоматически. Не угадывать по словарю «молоко → Молочные», если такой категории нет у пользователя (избегаем ложных срабатываний). Сопоставление только с **именами категорий пользователя**.

Общая категория на всю фразу: если до перечисления сказано «в продукты: хлеб, молоко» — все пункты получают «Продукты» (если категория с таким именем есть), пока у фрагмента нет своей явной категории.

### Задачи vs покупки

- Контекст вкладки задаёт тип сущности; автоопределения «задача vs покупка» нет.

### Приватность и сеть

- Без аккаунта приложения; дисклеймер про интернет; аудио не хранить; только системный STT.

### Доступность

- contentDescription у кнопки голоса; ручной ввод всегда доступен.

## Вне scope

- Wake word / фон
- Google Assistant App Actions
- Голосовое редактирование/удаление существующих
- Подзадачи, повторы, приоритет из речи
- Автосоздание категорий
- Онтологический словарь продуктов → категория без категорий пользователя
- On-device STT как обязательство
- Виджет (F-007)
